Decision/evidence revision: **October 6, 2026 (UTC)**. This is a research contract, not an Android implementation or provider-supported API specification.

## 3. Selected authentication, refresh and logout contract

**Prerequisite:** device-code authentication is beta; enable device login in personal ChatGPT security settings or through workspace-admin permissions. Organization policy is a stop condition, not an invitation to bypass it. The official auth page now lives under `learn.chatgpt.com`; the relevant device-code section was inspected, not inferred from navigation text.[92]

Selected fixed public client: `app_EMoamEEZ73f0CkXaXp7hrann`.[88] Use an honest own application User-Agent. Do not send a Codex Desktop originator/fingerprint or pretend to be Hermes/official Codex. Public client identity is not a secret and is not itself a permission grant.

| Stage | Exact source-backed request/behavior |
|---|---|
| Request device code | JSON POST `https://auth.openai.com/api/accounts/deviceauth/usercode`, `client_id` = selected ID |
| User sign-in | User manually opens `https://auth.openai.com/codex/device` in the **system browser** and enters the one-time code |
| Poll | JSON POST `https://auth.openai.com/api/accounts/deviceauth/token`, `device_auth_id`, `user_code`; Hermes uses interval floor 3 seconds and a 15-minute deadline |
| Pending status | **Only this poll stage:** HTTP 403/404 means authorization pending in the pinned reference; do not apply this meaning to usage GETs |
| Exchange | Form POST `https://auth.openai.com/oauth/token`; `grant_type=authorization_code`, `code=<returned authorization_code>`, returned `code_verifier`, selected `client_id`, `redirect_uri=https://auth.openai.com/deviceauth/callback` |
| Refresh | Form POST **same `/oauth/token`**; `grant_type=refresh_token`, current `refresh_token`, selected `client_id`; no independent-DCR resource/scope additions |

The device sequence and refresh payload above come from pinned Hermes, not a newly invented generic RFC device-flow endpoint.[87][88] No client secret or loopback listener is used by this selected device sequence. A server-returned verifier is part of this implementation; do not substitute a loopback/PKCE callback protocol.

**Future lifecycle design:** one serialized refresh per session; adopt a returned rotated refresh token, atomically persist the complete updated credential envelope, and generation-check the result. Never retry a consumed old token concurrently. Logout/account switch cancels polls/reads/refresh and rejects late callbacks. One bounded refresh/retry on a usage 401 is allowed under this contract; terminal refresh invalid-grant/reused-token or refresh-endpoint 401/403 requires reauthorization. Network/5xx/malformed response and 429 are distinct from terminal invalid credentials. Hermes's CLI-credential import/recovery paths are **not** part of this app.[87]

**Token lifetime is unknown for this selected grant.** Do not import the independent token-sharing reference's one-hour/30-day lifetime or guess a fixed TTL. Future expiry scheduling needs authoritative chosen-flow expiry metadata, clock/skew handling and native lifecycle tests. The Mac scratch did not refresh or persist tokens.

**Logout guarantee (future implementation): local only.** Stop requests, invalidate session/cache, delete local credentials and remove the associated key. Remote revoke for this chosen flow is unsupported/unverified; do not promise discovery-based revocation from the independent-DCR flow or claim signing out of all OpenAI sessions. Local deletion does not retract an already-in-flight request.

**Identity boundary:** the owner receipt says `exchange_succeeded_identity_unverified`. Receiving tokens does not validate account, audience, scopes or selected workspace. Current workspace/account identity is unverified and `ChatGPT-Account-Id` is **omitted**. Do not decode opaque metadata or convert email/subject into a workspace. Use a locally generated session generation for isolation, not a fabricated provider identity. M3a must establish an authoritative account-selection/isolation contract or stop and escalate before claiming native feasibility.

No Playwright/WebView login, cookie replay, CLI/browser credential import, auth-file export, inference/API call “to prove login,” hidden backend, purchases or reset activation is authorized.

## 4. Read-only endpoint and window contract

Only these authenticated data requests are selected:

| Surface | Request | Source-backed shape |
|---|---|---|
| Usage/windows + optional banked summary | GET `https://chatgpt.com/backend-api/wham/usage` | Rate flags, optional/null windows; `rate_limit_reset_credits.available_count` |
| Banked inventory | GET `https://chatgpt.com/backend-api/wham/rate-limit-reset-credits` | `available_count`, `credits[]`, status/type/grant/expiry fields |

The private paths and DTOs are implementation evidence, not a supported quota-reader API grant.[7][89][91] Bearer credentials stay local; do not log headers/bodies. Omit unknown account routing, desktop originator and `x-openai-codex-luna-reserve: 1`. The source's consume/reserve capability and alternate non-ChatGPT backend routes are **not** selected fallbacks.[7][15]

Windows carry `used_percent`, `limit_window_seconds`, `reset_after_seconds`, `reset_at`; `allowed` and `limit_reached` remain independent permission/status flags.[16][17] Identify **five-hour by 18000 seconds** and **weekly by 604800 seconds**, never just primary/secondary slot. A pinned CodexBar test puts weekly in primary and secondary null.[28][29]

Required interpretations:

- Absent/null window → unavailable with explicit reason; never invent zero usage/reset/duration.
- Unknown duration → unsupported/unknown; duplicate recognized durations → ambiguous, not arbitrary slot selection.
- Wrong type, Boolean-as-number, nonfinite value, negative duration/count or percent outside 0–100 → malformed; preserve a valid sibling.
- Percent does not grant/deny use: 100% with `allowed=true` and 0% with `allowed=false` are legitimate independent scenarios. Unknown plan text is not proof of ineligibility.[8]
- `reset_at` is an epoch-second instant; preserve relative reset seconds separately. Any relative-only derivation needs that endpoint's observation clock/provenance; conflicting absolute/relative values are a discrepancy, not silent coercion.[15][16]
- Passed reset → retain last percent, label reset due/stale and fetch again; do not synthesize a new zero or roll the date forward.
- Usage and inventory are separate GETs, not one atomic snapshot: retain **separate** successful observation clocks. The owner report supplied neither clock; its `observedAt` fields remain null. `retrievalDate` is documentation receipt date, not observation time.

**App timing choices, not provider promises:** foreground connect/resume/manual refresh; coalesced poll no faster than 60 seconds while visible; 30-second request deadline; stale after 15 minutes without a successful read. No exact alarms or permanent background service. Honor 429 `Retry-After` (delta or date), with bounded cancellable backoff; if it exceeds the operation deadline, defer rather than retry early. Account/session-generation checks discard late results. Generic GET 403 is forbidden/route permission, not automatically session expiry, an ineligible plan or zero quota.

Future M3b time display: absolute local date/hour plus relative days/hours using injected instant/zone/clock. Show `<1h` for a future sub-hour instant; passed resets say awaiting refresh. Compare epoch instants, refresh timezone and include UTC offset in repeated DST hours; never compare wall-clock hour labels alone.

## 5. Banked resets and final owner receipt

Banked resets are separate from purchased `credits.balance`, `has_credits` or `unlimited`; a purchased balance must never become a reset count.[15][89]
Inventory HTTP `expires_at` is `Option<String>` in first-party DTOs, with Z-string/null mock examples.[8][89]
The numeric camelCase app-server model is a different transformed protocol, not the direct HTTP field.[102]

Final sanitized evidence is `m0/fixtures/owner-reported-live.json`, an **allowlisted normalized receipt of owner-supplied output**, not a reconstructed backend body:

- Auth exchange HTTP **200**; chosen public-client kind; identity/scopes/workspace/mobile suitability unverified; account header omitted.
- Usage HTTP **200**, `allowed=true`, `limit_reached=false`, banked summary **2**. Primary duration **604800**, used **5%**, relative reset **488197** seconds, absolute reset **1791756793**. Secondary unavailable; no live five-hour claim.
- Inventory HTTP **200**, reported available **2**, inventory **2**, valid/not truncated; both rows provider-status available, shape valid and expiry known.
- Safe opt-in expiry strings: `2026-10-22T20:31:56.833553Z` → **1792701116** (October 22, 2026, 20:31:56 UTC); `2026-10-29T18:58:37.564252Z` → **1793300317** (October 29, 2026, 18:58:37 UTC). Original safe strings retain subsecond precision; normalized values are integer epoch seconds.

The old strict probe grammar admitted only 1–3 fractional digits, incorrectly leaving these six-digit strings unknown. The bounded fix admitted 1–6, and the owner then confirmed both known dates. The published research oracle reproduces that regression on the exact safe strings. It intentionally does not claim all ISO-8601 offsets/shapes are supported.

Preserve summary count, inventory count, each provider status and local expiry evaluation separately. **Missing/null/unsupported expiry stays unknown, not infinite.** An available row whose known expiry is passed, or a count/list discrepancy, remains a visible discrepancy; do not silently recompute the provider count. Entitlement expiry differs from quota window reset. No reset was consumed, purchased, activated or inferred from plan names.

## 7. Security and backup decisions (not implemented)

- Direct AndroidKeyStore **AES-256-GCM**, fresh randomized IV generated by the encryption cipher, authenticated version/provider/local-account-session envelope, serialized atomic replacement. App-private credential-protected ciphertext in `noBackupFilesDir`; no plaintext fallback.[42][77]
- Account-bound AAD means the authoritative provider account once established plus local session binding; do not derive a selected workspace from opaque token metadata. Keep keys/envelopes isolated per account/session and prevent stale-generation writes. Test tamper, key loss, disk/atomic-store failure and cancellation races in M3a.
- Direct platform APIs, not a new dependency on deprecated security-crypto APIs. Keystore protects key material, not plaintext while in use; hardware/StrongBox guarantees vary.[38][40]
- Explicitly exclude credentials from **both cloud backup and device transfer**, including supported legacy/new backup-rule formats. `noBackupFilesDir` is excluded; `allowBackup=false` alone does not disable device transfer on every Android 12+ implementation.[41] Restore/key loss/corruption → signed out; no silent key recreation over old credentials.
- No token/server export; no secrets/PII/raw responses/headers/callback URLs in logs, crash reports, backups or unsafe exception chains. ID-token hints are sensitive. Wipe cache/session on logout/account switch and minimize plaintext lifetime; garbage collection is not a promised secure zeroization mechanism.

Native storage/lifecycle acceptance must cover cancellation/process death, restart/account switch, concurrent refresh rotation and atomic write-back, local logout/key deletion, tamper/key loss, backup/restore/device transfer and late callbacks. None is measured at M0.

## 9. Accepted coverage contract

**>=95% JaCoCo INSTRUCTION on ALL handwritten production bytecode.** This is bytecode instruction coverage, not statement coverage; LINE/BRANCH remain diagnostics.[36] M0 has no Android production classes, so application coverage is **not measured and not waived**. The research verifier is not application production code. No custom statement analyzer is selected.

1. Audit all handwritten production sources and the complete original nonminified class universe, including never-loaded code, UI/platform/storage/security/coroutines/error/cancellation. Freeze only genuinely generated/dependency exclusions with justification; no blanket handwritten packages, `$`, `*Kt`, lambdas, Compose or `invokeSuspend` exclusions. Pin/disclose JaCoCo compiler filters separately; do not inflate the result by hand-excluding difficult code.
2. Bind each original FQN/class SHA-256/JaCoCo class ID/probe count to exact source revision, variant, compiler/instrumenter and run/attempt. Class names alone do not establish compatible identity; same-FQN/different-bytecode and probe-topology mismatch must fail.[45]
3. Prove JVM/Robolectric and native/D8 probes correspond to **that same class universe**; union compatible execution probe hits, then produce one report against all original classes. Never add XML percentages/overlapping covered counts or take per-class maxima.[45]
4. From report INSTRUCTION C=covered, M=missed, require nonempty denominator and exact `100*C >= 95*(C+M)`, not rounded display percent. Missing required JVM/native data or failed required tests blocks acceptance.
5. Publish counts/unrounded ratio, source/variant/compiler/instrumenter, run/attempt/native target, hashes of inputs/classes/report, exclusion/filter manifest and test reports. Native behavior PASS and coverage PASS are separate gates.

M2 must prove the compatible JVM/native union pipeline; later handwritten app additions remain in its denominator and full gates. No M0 receipt or empty denominator substitutes for that future gate. TDD ordering is not mandatory; meaningful behavior tests and independent review remain mandatory.

## 10. Deferred FIRST M3a stop/go and escalation

Before native feasibility is accepted, M3a must execute the chosen flow on Android: system-browser device entry/poll/exchange/cancellation/process lifecycle; authoritative account/selection/isolation handling; serialized refresh/rotation/atomic encrypted storage/local logout; storage/backup failure modes; and both actual read endpoints with honest identity and sanitized observations. No duplicate M0 APK is required or authorized.

**Stop on auth, account/selection, storage, lifecycle or endpoint failure.** Preserve categorical sanitized evidence and escalate. Do not silently switch registration/client/redirect method, import cookies/CLI credentials, add a backend, bypass policy/CAPTCHA, impersonate the desktop app, make inference calls, buy/activate resets, omit banked detail, or broaden scope. Any new workaround, backend requirement or unresolved mandatory field needs a new owner decision. Unknown future expiry must be shown as unknown; if the required availability/count/expiry contract cannot be fulfilled, escalate rather than declaring it zero/infinite.

Residual risks accepted for M0: private-service instability, public-client distribution permission unverified, device beta/org restrictions, unverified current identity/scopes/workspace, account-specific absent five-hour window, untested chosen-flow refresh/logout and unproven Android/Keystore lifecycle. They are explicit future gates, not hidden M0 execution results.
